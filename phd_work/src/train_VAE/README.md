# Вариационный автокодировщик (VAE) для данных Telescope Array

Документация к модулю `train_VAE` — описание архитектуры, данных, функции потерь и гиперпараметров для статьи.

---

## 1. Постановка задачи

Модель обучается на симулированных ливневых событиях детекторного массива Telescope Array (TA). Каждое событие представляет собой **переменную по длине последовательность срабатываний детекторов**.

**Цель обучения:**
- научиться сжимать событие в компактное латентное представление (энкодер);
- восстанавливать сигналы и времена детекторов из латентного кода (декодер);
- получить латентное пространство, пригодное для разделения типов частиц (протон / фотон) по ошибке реконструкции или по геометрии латента.

Модель относится к классу **InfoVAE**: помимо реконструкции используется регуляризация латентного пространства через **MMD** (Maximum Mean Discrepancy) к стандартному нормальному распределению. KL-дивергенция в финальной конфигурации **отключена** (коэффициент = 0).

## 2. Входные данные

### 2.1. Формат хранения

Данные хранятся в HDF5-файле. Текущий датасет:

```
Ivan_Kharuk_pr_ga_all_0001_eq_eff_normed_one_work.h5
```

Структура файла:
- `train/`, `test/` — обучающая и тестовая выборки;
- `norm_param/dt_params/{mean, std}` — параметры нормализации признаков детекторов;
- `norm_param/recos/{mean, std}` — параметры нормализации параметров реконструкции.

### 2.2. Признаки одного детектора (`dt_params`)

Исходно 6 признаков на детектор (до предобработки):

| Индекс | Название | Единицы | Описание |
|--------|----------|---------|----------|
| 0 | x | 1200 м | Координата детектора относительно ядра ливня |
| 1 | y | 1200 м | Координата детектора относительно ядра ливня |
| 2 | z | 1200 м | Высота детектора |
| 3 | signal | MIP | Амплитуда сигнала |
| 4 | flat time | мкс | Время прихода фронта плоскости |
| 5 | real − flat | мкс | Время формы относительно фронта плоскости |

Все признаки **нормированы** (z-score) по обучающей выборке; параметры нормализации хранятся в `norm_param`.

### 2.3. Объединение временных признаков (`make_real_time: True`)

При `make_real_time = True` два временных канала объединяются в один:

```
Time = flat_time + (real_time − flat_time) = real_time
```

Затем `Time` нормируется по среднему и стандартному отклонению внутри выборки. В итоге на вход модели подаётся **5 признаков** на детектор:

| Индекс | Признак |
|--------|---------|
| 0 | x |
| 1 | y |
| 2 | z |
| 3 | signal (log-нормированный сигнал) |
| 4 | Time (объединённое время) |

Соответствует `input_dim: 5` в конфигурации.

### 2.4. Параметры реконструкции события (`recos`)

Вектор из 15 параметров, полученных стандартной реконструкцией TA:

| Индекс | Параметр |
|--------|----------|
| 0 | θ (zenith) |
| 1 | φ (azimuth) |
| 2 | S₈₀₀ |
| 3 | E_γ |
| 4 | d_border (км) |
| 5 | χ²/ndof |
| 6 | кривизна фронта Linsley |
| 7–14 | AOP, S_b, суммарный сигнал, асимметрия, число пиков и др. |

В латентный вектор декодера подаются **индексы 0, 1, 2** (`index_recos: [0, 1, 2]`) — углы и S₈₀₀.

### 2.5. MC-параметры события (`mc_params`)

| Индекс | Параметр |
|--------|----------|
| 0 | номер события |
| 1 | тип частицы (CORSIKA: 1 — γ, 14 — p, 5626 — Fe) |
| 2 | номер ближайшего к ядру детектора |
| 3 | **mc_E** — энергия первички |
| 4 | mc_θ |
| 5 | mc_φ |
| 6 | высота первого взаимодействия, км |
| 7–8 | координаты ядра |
| 9 | расстояние до границы массива, км |

Индекс `3` (энергия) указан в `reconstruction_params` для вспомогательной головы декодера (в текущей конфигурации `koef_mass = 0`, т.е. этот лосс не используется).

### 2.6. Типы частиц в выборке

| Режим | Частицы | Вероятность включения |
|-------|---------|----------------------|
| train | proton (`pr`), photon | `[1.0, 0.0]` — **только протоны** |
| test | proton, photon | `[1.0, 1.0]` — оба типа |

Фотоны в обучении отключены (`train_probability: [1.0, 0.0]`), чтобы модель училась на протонном фоне и затем детектировала аномалии (фотоны) по ошибке реконструкции.

### 2.7. Формирование последовательности

Для каждого события строится последовательность:

```
[CLS] → детектор₁ → детектор₂ → … → детекторₙ → [STOP]
```

| Токен | Значение | Описание |
|-------|----------|----------|
| CLS | обучаемый (`CLS_token: trainable`) | Агрегирует информацию о событии; первый элемент последовательности |
| STOP | −10.0 | Маркер конца последовательности |
| PAD | −11.0 | Заполнение до максимальной длины в батче |

Стартовый токен `hard_v1` (до замены на CLS): `[0, 0, 0, −0.278, −8.798 + 15.595]` — минимальные нормированные значения сигнала и времени.

## 3. Архитектура модели

Класс `VAE` (`model.py`). В финальной конфигурации используется **Transformer-энкодер** + **полносвязный декодер**.

### 3.1. Энкодер: `Encoder_Kharuk_idia`

Гибридная архитектура на базе Transformer:

```
Вход [B, N, 5]
    ↓ Linear(5 → 64)          — embedding
    ↓ TransformerEncoder × 2  — self-attention по всем токенам
    ↓ CLSCrossAttention × 2   — cross-attention: обновляется только CLS-токен
    ↓ Linear(64 → 32) + LeakyReLU
    ↓ Linear(32 → 6)  → μ
    ↓ Linear(32 → 6)  → log σ²
```

**Параметры Transformer-слоёв:**

| Параметр | Значение |
|----------|----------|
| `hidden_dim` (d_model) | 64 |
| `nhead` | 4 |
| `dim_feedforward` | 512 |
| `dropout` | 0.1 |
| `num_base_transformer_layers` | 2 |
| `num_cls_update_layers` | 2 |
| `latent_dim` | 6 |

**Маскирование:** токены с `padding_value = −11` и `stop_token = −10` исключаются из attention. CLS-токен (позиция 0) никогда не маскируется.

**Репараметризация (трюк VAE):**

```
z = μ + ε · exp(0.5 · log σ²) · reparameterize_koef,   ε ~ N(0, I)
```

`reparameterize_koef = 1.0`.

**Добавление параметров реконструкции в латент (`recos_in_latten: True`):**

```
z_aug = concat(z, recos[:, [0, 1, 2]])   → размерность 6 + 3 = 9
```

В латент добавляются θ, φ, S₈₀₀ из стандартной реконструкции TA.

### 3.2. Декодер: `DecoderFullyConnected`

Для каждого детектора `i` независимо предсказываются 5 выходных признаков:

```
Вход на детектор i: concat(z_aug, x_i, y_i, z_i, length)   → 9 + 3 + 1 = 13
    ↓ MLP: 13 → 64 → 128 → 512 → 128 → 64 → 32 → 5
```

Координаты `(x, y, z)` детектора **передаются декодеру явно** (teacher forcing) — декодер восстанавливает только сигнал и время, не координаты.

Длина последовательности (`length`) — число реальных детекторов в событии (без CLS/STOP/PAD), вычисляется энкодером.

### 3.3. Аугментация при обучении (denoising)

В режиме `model.train()` к нормированным каналам сигнала и времени добавляется гауссов шум:

```
x[:, :, 3] += denoise_koef · ε,   ε ~ N(0, 1)   — сигнал
x[:, :, 4] += denoise_koef · ε                   — время
```

`denoise_koef = 0.05`.

### 3.4. Альтернативные архитектуры (не используются в финальной конфигурации)

В коде также реализованы, но закомментированы:
- `Encoder` — LSTM-энкодер;
- `Encoder_Transformer` — чистый Transformer + VAE;
- `Encoder_Transformer_AE` — автоэнкодер без log σ²;
- `DecoderRNN` — LSTM-декодер (seq2seq);
- `DecoderTransformer` / `DecoderTransformerSimple` — Transformer-декодеры.

## 4. Функция потерь

Общий лосс (`loss.py`, функция `vae_loss`):

```
L = L_recon + β_KL · L_KL + λ_DL · L_num_det + λ_mass · L_recon_params + λ_MMD · L_MMD
```

### 4.1. Реконструкция `L_recon`

MSE по признакам детекторов с маскированием:

```
L_recon = (1 / N_active) · Σ_{активные детекторы} Σ_j  w_j · (x̂_ij − x_ij)²
```

где `w_j` — веса по признакам (`koef_loss`), `N_active` — число активных детекторов в событии.

**Веса признаков** (`koef_loss: [0, 0, 0, 1, 1]`):

| Индекс | Признак | Вес |
|--------|---------|-----|
| 0 | x | 0 |
| 1 | y | 0 |
| 2 | z | 0 |
| 3 | signal | **1** |
| 4 | Time | **1** |

Координаты **не штрафуются** — они передаются декодеру напрямую. Оптимизируются только сигнал и время.

Маска активных детекторов: исключаются PAD (−11), START (CLS) и STOP (−10) токены.

### 4.2. KL-дивергенция `L_KL`

Стандартная формула VAE:

```
L_KL = −0.5 · Σ_k (1 + log σ²_k − μ_k² − σ²_k)
```

**В финальной конфигурации отключена:**

```yaml
koef_KL:
  start: 0.0
  end: 0.0
```

Поддерживается β-VAE расписание: линейный рост коэффициента от `start` до `end` между эпохами `start_it` и `end_it`.

### 4.3. Потеря по числу детекторов `L_num_det`

```
L_num_det = (N_real − N_pred)²
```

**Отключена:** `koef_DL = 0.0`.

### 4.4. Потеря по MC-параметрам `L_recon_params`

MSE между предсказанием вспомогательной головы декодера и истинной энергией `mc_E`.

**Отключена:** `koef_mass = 0.0`.

### 4.5. MMD-регуляризация `L_MMD` (InfoVAE)

Приводит распределение латентных кодов μ к стандартному нормальному:

```
L_MMD = E[k(z, z')] + E[k(z_p, z_p')] − 2·E[k(z, z_p)]
```

где `k` — гауссово ядро с `σ = 1.0`, `z` — латентные коды батча, `z_p ~ N(0, I)`.

**Коэффициент:** `koef_MMD = 0.05` (подобран как оптимальный).

### 4.6. Сводная таблица коэффициентов

| Коэффициент | Значение | Роль |
|-------------|----------|------|
| `koef_loss` | `[0, 0, 0, 1, 1]` | Веса MSE по признакам |
| `koef_KL` | 0 → 0 | KL-дивергенция (выкл.) |
| `koef_MMD` | **0.05** | MMD-регуляризация латента |
| `koef_DL` | 0.0 | Число детекторов (выкл.) |
| `koef_mass` | 0.0 | MC-энергия (выкл.) |
| `reparameterize_koef` | 1.0 | Масштаб шума в reparameterize |
| `denoise_koef` | 0.05 | Шум при обучении |

**Итоговая функция потерь:**

```
L = L_recon + 0.05 · L_MMD
```

## 6. Метрики оценки

### 6.1. `LatentMetric`

На тестовой выборке (протоны + фотоны):
1. **UMAP** проекция латентных векторов μ;
2. **CatBoost-классификатор** (depth=6, 10000 итераций) по латенту → F1-score;
3. Confusion matrix.

F1 по латенту используется для выбора лучшего чекпоинта (`best`).

### 6.2. `DivedeMetrics`

Разделение протон / фотон **без обучения классификатора** — по скалярным величинам:
- **L_recon** — ошибка реконструкции (ROC, AUC);
- **‖μ‖₂** — радиус латентного вектора (ROC, AUC);
- TPR/FPR vs порог отсечения.

Это основной метод детекции γ-аномалий: модель, обученная на протонах, даёт большую ошибку реконструкции на фотонах.

## 7. Схема архитектуры

```
Событие: [CLS, det₁, det₂, …, detₙ, STOP]  — каждый detᵢ ∈ ℝ⁵
                    │
                    ▼
         ┌──────────────────────┐
         │  Encoder_Kharuk_idia │
         │  Transformer × 2     │
         │  CLS-CrossAttn × 2   │
         └──────────┬───────────┘
                    │ μ, log σ²  (6D)
                    ▼
              z ~ N(μ, σ²)      (reparameterize)
                    │
                    ├── concat recos[θ, φ, S₈₀₀]  → z_aug (9D)
                    │
                    ▼
         ┌──────────────────────┐
         │ DecoderFullyConnected│
         │  для каждого detᵢ:   │
         │  MLP(z_aug, xᵢ,yᵢ,zᵢ,│
         │       length) → ℝ⁵   │
         └──────────┬───────────┘
                    ▼
         Реконструкция [signal, Time]
```

## 10. Ключевые особенности для статьи

1. **Переменная длина событий** — LSTM/Transformer с padding mask; длина события от единиц до ~100 детекторов.
2. **Teacher forcing координат** — декодер получает истинные (x, y, z), восстанавливает только физические наблюдаемые (сигнал, время).
3. **Обучение только на протонах** — unsupervised anomaly detection: фотоны как out-of-distribution.
4. **InfoVAE с MMD** вместо KL — `koef_MMD = 0.05` обеспечивает регуляризацию без размытия латента.
5. **Контекст реконструкции TA** — углы и S₈₀₀ из стандартной реконструкции подаются в декодер через конкатенацию с латентом.
6. **Denoising** — устойчивость к шуму в сигнале и времени (`denoise_koef = 0.05`).
7. **CLS-токен** — обучаемый агрегирующий токен по аналогии с BERT; обновляется через cross-attention, не через self-attention.
